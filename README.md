あにまんというサイトの過去ログ（https://bbs.animanch.com/kakolog/） の情報をまとめるためのもの  
1.URL抽出ページ  
各スレッドのタイトル、コメント数、URLを抽出し、エクセル出力するもの  
2.台本作成ページ  
スレッドURLを入力するとYMM4に自動読み込みが出来るcsvファイルを作成する。  
3.動画作成ページ  
台本ファイル（csv）からVOICEVOXで音声を合成し、反応集動画（mp4）を作成する。  
出力先：`scraping_project/出力動画/`（動画・字幕srt・サムネイル画像）  

### 動画作成の準備
- [VOICEVOX](https://voicevox.hiroshiba.jp/) を起動しておく（エンジンが http://127.0.0.1:50021 で待ち受ける）
- [ffmpeg](https://ffmpeg.org/) をインストールしてPATHを通す（または環境変数 `FFMPEG_PATH` にffmpeg.exeのパスを設定）
- `pip install -r requirements.txt`

### 使い方
1. 台本作成ページでスレッドURLから台本csvを作成（必要ならExcel等で不要なレスを削除・編集）
2. 動画作成ページで台本を選び、背景画像・BGMを指定して作成  
   コマンドラインからも作成可能：`python make_video.py 台本名.csv --background 背景.png --bgm bgm.mp3`  
   `--silent` を付けるとVOICEVOXなしでレイアウト確認用の動画を作成する

### 話数感想スレの反応集動画を作る
1. 反応集台本作成ページで感想スレのURLを指定する。取得が拒否される場合は、ブラウザでスレを開いて「ウェブページ、完全」で `scraping_project/保存スレ/` に保存し、一覧から選ぶ
2. レスの選別・話題ごとの並べ替え・スレの画像のコマ収集（`scraping_project/コマ画像/`）が自動で行われ、台本csvができる。話題はキャラ単位（`感想サイト/data.json` の別名をまとめる）で分け、返信は返信先の直後に並べる。絵文字だけのレスや、元のレスがないと意味が通らない短いレス（「それな」等）は外し、半角カナ・絵文字・「www」は読み上げ用に整える。作り手の案内のセリフは入れない。コマは白黒の画像（漫画の切り抜き）だけを集め、画像のレス自身・その返信・本文のキーワードが共通するレスにだけ割り当てる
3. コマは台本の3列目（コマ画像）を書き換えれば後から追加・差し替えできる。空欄の行は話題名を表示する
4. 動画作成ページで台本を選ぶと、中央にコマ・下部に字幕のレイアウトで動画と説明文（`_説明文.txt`）が出力される

### 背景にフリー動画を使う（反応集の台本のみ）
- フリー動画を `scraping_project/背景動画/` に置き、動画作成ページで選ぶ（既定はランダム）。短い動画はループし、縦横比が違う動画は切り抜いて画面を埋める
- Pexelsから自動取得する場合は無料のAPIキーを取得して環境変数 `PEXELS_API_KEY` に設定し、動画作成ページに検索キーワードを入れる
- 素材のライセンスは配布元の条件を確認する。背景動画ありの作成は書き出しに時間がかかる

### サムネイルを作る
- サムネ作成ページで台本を選ぶと、台本から吹き出し4つ・下部の文字・コマが初期入力される。修正して作成すると `出力動画/<タイトル>_thumbnail.jpg` に出力する
- 修正内容は台本の `.meta.json` に保存され、動画を作り直しても上書きされない。動画作成時は保存した設定で自動出力する（未設定なら初期値）
- 見た目の種類は `app/contorollers/thumbnail_template.py` の `TEMPLATES` で追加できる

あにまん掲示板のコンテンツ使用規約（ https://bbs.animanch.com/board/905570/ ）に従うこと
- 使用できるのは過去ログのスレのみ（現行スレは台本作成を中止する。削除されたスレは使用禁止）
- YouTube説明文の先頭に元スレのURLを全て記載する（`_説明文.txt` の先頭に自動で入る。投稿時に動かさない）
- 動画内の先頭に掲示板名『あにまん掲示板』を記載する（1画面目に自動で入る）
- 手持ちの画像が自動収集の判定でコマになるかは `python check_panels.py 画像フォルダ`（`scraping_project/` で実行）で一覧確認できる
- 創作イラストの転載は禁止。本文から明らかなものは収集しないが完全には判定できないため、公開前に `コマ画像/` を目視で確認する
- ステルスマーケティングでの使用、掲示板の規約で禁止されているスレ・レスの使用は禁止

### 感想サイトの画像を集める
1. 感想サイト画像収集ページで作品を選び、話数（`129`、`129-131`、`最新`）を入力する
2. 保存しているサイトで該当の記事を探し、`scraping_project/参考画像/<作品>/<サイト>/<N>話 画像/` に本文の画像を保存する
3. 記事に出典が書かれた画像（「出典:ONE PIECE 102巻」「© 作者 137話より」等）は、`<N>話 画像/出典 102巻/` のように出典ごとのサブフォルダに分ける。画像ごとのURLと出典は `取得元.txt` に残る

- 作品とサイトのURLは `scraping_project/感想サイト/data.json` にある。作品を増やすときはここに追記する
- 保存済みの話は取得し直さない。記事は作品名と話数がタイトルに入ったものを探し、見つからないサイトは結果に表示される
- 記事が見つからないときは理由を表示する（まだ公開されていない、更新待ち、この話だけ記事がない、話数を判定できない）
- 依頼のたびに保存サイトと候補の最新話を確認する（1作品1分ほどかかる）。公開済みの最新話から3話以上遅れているサイトは更新をやめたとみなし、「過去のサイト」に移して `data.json` の候補（candidates）から差し替える。過去のサイトも最後に更新していた話までは画像の取得に使う
- 記事はあるのに画像がない回が2回続いたサイトは、文章だけのサイトとみなして外し（`excluded_sites`）、候補から差し替える
- 作品の別名（`ONE PIECE` 等）は `data.json` の aliases に書く。サイト名に作品名が入った専門サイトは、記事タイトルに作品名がなくても話数で探す
- 話数は「55話」「第55話」「#55」の書き方を読む。「◯話以降」「予想」「早バレ」「確定速報」「アニメ」の記事は話数として扱わない。会話形式のアイコンや商品紹介の画像は保存しない。発売前に流出した雑誌の写真を載せるサイト（gorilife.com）は使わない
- 白黒のコマに色付きの文字・枠を重ねた加工画像は保存せず、`取得元.txt` に「除外」と残す。電子版等のカラーページは残す。カラー画像に重ねた文字、白黒の文字入れ、コマの貼り合わせは判別できない
- 集めた画像は反応集動画のコマにも使える。画像の権利は作品の権利者にあるので、公開前に内容を確認する

### 反応集の台本のコマを、コメントに合わせて割り当てる
1. 感想サイト画像収集でその話と1つ前の話の画像を集める
2. `scraping_project/` で `python assign_panels.py 台本名.csv 作品名 話数 --sheet 出力フォルダ` を実行し、一覧画像を見て、説明のない画像（「未」）に `--describe 番号="誰が・どんな場面か・セリフ"` で説明を書く
3. `python assign_panels.py 台本名.csv 作品名 話数` を実行する（`--lines 2` で2セリフごとに1枚）
4. 台本の3列目（コマ画像）が書き換わり、理由の一覧が `台本ファイル/<台本名>.コマ割り当て.txt` に出る。合わない場面は `--fix 3-4=12`（行範囲=候補番号）で差し替え、動画作成ページで動画を作る

- 候補の順番: スレの画像（レス自身か返信先が貼った画像は最優先）→ その話 → 1つ前の話。それより古い話は「前回」「回想」「◯巻」などの言葉があるか、強く合うときだけ使う
- 手がかりは、画像の説明（一番重い。蓄積されて次回も使われる）、記事で画像の前後に書かれた文章（`画像情報.json`）、吹き出しの文字の読み取り結果（`文字読み取り.json`）。文章と読み取りは画像を集めたときに作られるので、画像集めは1話あたり数分かかる
- コメントのキャラ名・語句と重なる画像、セリフを引用したコメントは吹き出しの文字が一致する画像を選ぶ。合う画像がなければ無理に切り替えず、前の画像を最大3場面まで続ける。直近に使った画像は避ける
- キャラの別名（「潔」「世一」等）は `data.json` の characters にある。画像を集めたときに、記事の『潔 世一』『ミヒャエル・カイザー』のような書き方から自動で足される（足した名前は結果に表示。複数のキャラに共通する姓は足さない）。あだ名は手で追記する。吹き出しの読み取りには `manga-ocr` と `opencv-python-headless` が必要（初回にモデルを自動で取得する）

### 読み上げの読み間違いを直す
- キャラ名などの読みは、動画作成のときに VOICEVOX のユーザー辞書へ自動で登録する（字幕の表記は変わらない）
- 作品の読みは `scraping_project/感想サイト/data.json` の作品の `readings`、作品に関係ない語（草＝クサ等）は `app/contorollers/reading_dict.py` の `COMMON_READINGS` に書く
- `scraping_project/` で `python check_readings.py 台本名.csv` を実行すると、各行の読み（カタカナ）が `台本ファイル/<台本名>.読み.txt` に出る。読み間違いを見つけたら上の辞書に足す
- スコア「3-2」は読み上げるときだけ「3対2」に書き換える

### スマホからこのPCで実行する
1. PCで `scraping_project/start_for_smartphone.bat` を実行する（PowerShell等なら `APP_HOST=0.0.0.0` を環境変数に設定して `python run.py`）
2. 画面に表示された `http://192.168.x.x:5000` をスマホのブラウザで開く（PCとスマホは同じWi-Fi）
3. 開けない場合はWindowsファイアウォールでPython(ポート5000)の受信を許可する

- 作成処理は**PC上で**実行されます。VOICEVOX・ffmpegもPC側で起動・用意しておいてください（VOICEVOXエンジンURLは `http://127.0.0.1:50021` のままでOK）
- 外出先から使う場合は [Tailscale](https://tailscale.com/) をPCとスマホに入れ、表示されるTailscaleのIPで `http://<TailscaleのIP>:5000` を開く（ルーターのポート開放はしないこと。認証がないため）
- 外部公開モードではFlaskのデバッグモードは自動的にOFFになる。ポート変更は `APP_PORT` で指定
